Embeddings: turning meaning into numbers

By the end you can
1. Say what an embedding is without using the word "vector".
2. Read a similarity score and tell whether two texts are related.
3. Write the function that compares two embeddings.
01 / Start here

The idea in plain words

Computers compare numbers easily and meaning badly. An embedding closes that gap: it turns a piece of text into a list of numbers, chosen so that texts with similar meanings get similar lists.
Think of a library. Books on the same subject sit on the same shelf, so a book's location tells you what it is about. An embedding is a shelf location for a sentence. Nearby locations mean related meanings.
EmbeddingA list of numbers that stands for the meaning of some text.
VectorThe maths word for a list of numbers. Picture an arrow from the centre of a map to a point.
DimensionOne number in the list. Real models use hundreds. The picture below uses two.
Common mix-up
An embedding model does not look words up in a dictionary. It learned from a huge amount of text that words used in similar sentences should sit close together.
02 / See it

Pick a word and watch what lands near it

Each arrow is one word. Arrows that point in nearly the same direction have nearly the same meaning. The score is called cosine similarity: 1.00 means the same direction, and a score near 0 means unrelated.

Why direction?
Two arrows can be different lengths and still point the same way. Comparing direction ignores length, which is why cosine similarity is the usual default for text.
03 / Worked example

Three lines that make real embeddings

from sentence_transformers import SentenceTransformer

model = SentenceTransformer("all-MiniLM-L6-v2")
vectors = model.encode(["a puppy asleep on the couch", "how to change a flat tire"])
print(vectors.shape)   # (2, 384)
model = ... loads a small, free embedding model that runs on a laptop.
model.encode(...) turns each sentence into one vector.
(2, 384) means two sentences went in and two vectors came out, each with 384 numbers.
Where this fits in RAG
You embed every chunk of your documents once and store the vectors. When a question arrives you embed it with the same model and fetch the chunks whose vectors point closest to it. That fetch is the "retrieval" in retrieval-augmented generation.

05 / Your turn

Write the comparison yourself

Finish the function so it returns the cosine similarity of two vectors. You have seen everything you need.
Divide the dot product of a and b by the product of their lengths. np.dot gives the first and np.linalg.norm gives a length.

06 / Recap

What to carry into the next lesson

1. An embedding is a list of numbers that stands for meaning.
2. Similar meanings give arrows that point the same way, and cosine similarity measures that.
3. RAG embeds documents and questions with the same model, then matches them by direction.
